# Входящие

Сервис для Vercel читает новые письма общих ящиков Yandex 360, разбирает текст и по ручным правилам создаёт уведомление в Битрикс24, автоматический ответ или пропускает письмо. Первое подходящее правило останавливает проверку.

Папка «Спам» не открывается. Исторические письма при первом подключении не загружаются. Сервис не помечает, не перемещает и не удаляет входящие: IMAP открывается только на чтение, тело запрашивается через `BODY.PEEK`.

## Что делает обработка

Для каждого нового письма сохраняются заголовки, имена вложений без их содержимого и нормализованный текст. Из текста извлекаются телефоны, email, ссылки, даты, дедлайны, суммы и номера договоров, счетов, актов и заявок. Язык, тональность и срочность считаются локальными словарями, без внешнего LLM.

Если ни одно правило не подошло, письмо сохраняется как «пропущено без правила». Уведомление по умолчанию не содержит полный текст. Автоответ уходит через SMTP один раз и не создаётся для автоответов, рассылок и служебных адресов.

Глобальный сухой прогон включён по умолчанию: правила считаются, а Битрикс24 и SMTP не вызываются.

## Локальный запуск

```bash
docker compose up -d
cp .env.example .env
npm run secrets
```

Вставьте выданные значения в `.env`, задайте `ADMIN_USERNAME`, `DATABASE_URL` и `DATABASE_URL_UNPOOLED` (локально они совпадают), затем:

```bash
npx prisma migrate deploy
npm run dev
```

Админка откроется на `http://localhost:3000`.

## Vercel

- Runtime функций: Node.js. IMAP и SMTP не работают на Edge.
- Подключите PostgreSQL и выполните `npx prisma migrate deploy`.
- Задайте `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `AUTH_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ENCRYPTION_KEY`, `CRON_SECRET`. Neon на Vercel создаёт оба адреса базы сам.
- `vercel.json` на тарифе Hobby запускает опрос раз в сутки в 09:00 МСК и отправку очереди в 09:15 МСК. Чаще одного раза в день cron на Hobby недоступен; почту можно проверить кнопкой «Проверить почту сейчас». На Pro можно вернуть интервалы `*/5` и `*/2`.
- Секрет cron Vercel должен совпадать с `CRON_SECRET`.

Проверка живости: `GET /api/health`.

## Как включать боевой режим

1. Создайте один тестовый ящик и добавьте базовые исключения.
2. Оставьте глобальный сухой прогон включённым.
3. Добавьте одно-два правила и шаблон ответа, тоже в сухом прогоне.
4. Несколько дней смотрите письма, сущности, пропуски и ложные срабатывания.
5. Только после этого переключите Битрикс24 на веб-хук и снимите сухой прогон.

Пароли IMAP, SMTP и URL веб-хука шифруются `AES-256-GCM`. В логах нет паролей и полных тел писем.

## Проверки

```bash
npm test
```

Тесты покрывают разбор текста, кодировки, сущности, правила first-match-wins, подавление автоответов, рабочие часы и шифрование. Подключение к живому ящику проверяется кнопками IMAP и SMTP в карточке ящика.
